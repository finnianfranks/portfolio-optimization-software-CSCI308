Formally, this is a final project for the course CSCI-308, programming language design. However, I was give complete control over the direction and intention of the project and therefore consider it more of a personal/passion work. 
The goal of the work done here was to demonstrate and build knowledge using OCaml. In the code, OCaml's functional paradigm has been completely embraced. Often there were interactions that could have been performed with for loops and
imperative stlye problem solving, and efforts were taken to instead apply a functional lense.

The question defined for the project is as follows: the computer is given 10 tickers to choose from. The user may define the size of a portfolio they would like to build from the available tickers. The computers job is to return to the user the 
portfolio which optimizes the sharpe ratio. Optimizing the sharpe ratio is an incredibly simplified explantion of what is actually taking place. More specifically we are solving for the monthly sharpe ratio. That is, our sharpe ratio is calculated
using timesteps of months. Specifically we look back 5 years and collect 60 data points for each ticker, each one being the closing price of the first day of the month. 

The files of the project are split into the research and notes that went into solving the problem, the python files, and the OCaml files. The research notes are self explanatory and list useful citations. The python folder is used only to fetch
the data that we need to analyze. This is done using the yfinance library. We simply call this file fetch.py since all it is doing is fetching a csv for us to use. The Ocaml folder contains all of the relevent OCaml and Opam project files and 
configuration. We use outside modules Csv and Combinat. Csv is used to work with the data from the csv provided by python. Combinat is used to perform combinatorial logic on our list of tickers such that we may create and analyze subgroups. The 
main.ml file contains the general execution flow of the code. Comments are left on each subsequent OCaml file to help users navigate. Additionally debugging notes are left to show users how to easily debug the project and where operations 
failed at a certain point.

The project can be taken further in numerous different ways. Some possible ideas are to allow the user to provide the pool of stock tickers they want to work with. Then OCaml would have to work with python in order to generate a csv for any
possible tickers the user provides. Another idea is to enhance the code through refactoring and more parameterization. Since this project can be considered rudimentary OCaml there exists a lot of code which can be refactored and parameterized,
such as the number of data points the csv contains which is currently hardcoded. Some future ideas generated by this project is to create a combinatorial logic module from scratch or perhaps contribute to the existing one.
